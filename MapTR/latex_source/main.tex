\begin{abstract}
% background and significance
高精地图（High-definition Map, HD Map）提供了驾驶场景丰富且精确的环境信息，是自动驾驶（Autonomous Driving）系统中规划模块的基础性和不可或缺的组成部分。
本文提出MapTR——一种面向高效在线向量化高精地图构建（Online Vectorized HD Map Construction）的结构化端到端（End-to-End）Transformer。本文提出统一的排列等价建模（Permutation-equivalent Modeling）方法，即将地图元素（Map Element）建模为带有等价排列（Equivalent Permutations）集合的点集（Point Set），该方法准确描述地图元素形状并稳定学习过程。本文设计层次化查询嵌入（Hierarchical Query Embedding）方案以灵活编码结构化地图信息，并执行层次化二分匹配（Hierarchical Bipartite Matching）进行地图元素学习。
在nuScenes数据集上，MapTR仅凭相机输入即在现有向量化地图构建方法中达到最优性能和效率。具体而言，MapTR-nano在RTX 3090上实现实时推理速度（25.1 FPS），比现有基于相机的当前最优（State-of-the-Art, SOTA）方法快8倍，同时mAP高5.0。即使与现有当前最优多模态（Multi-modality）方法相比，MapTR-nano的mAP高0.7，MapTR-tiny的mAP高13.5且推理速度快3倍。丰富的定性结果表明，MapTR在复杂多样的驾驶场景中保持稳定鲁棒的地图构建质量。MapTR在自动驾驶中具有重要的应用价值。代码和更多演示见 \url{https://github.com/hustvl/MapTR}。
\end{abstract}


\section{引言}
高精地图是针对自动驾驶专门设计的高精度地图，由地图元素的实例级向量化表示组成，包括人行横道（Pedestrian Crossing）、车道线（Lane Divider）、道路边界（Road Boundary）等。高精地图包含道路拓扑和交通规则的丰富语义信息，对自动驾驶车辆导航至关重要。

传统上，高精地图通过基于SLAM的方法~\citep{loam,legoloam,liosam}进行离线构建，流程复杂且维护成本高。近年来，在线高精地图构建受到越来越多关注，该方法利用车载传感器在运行过程中实时构建自车周围地图，摆脱了离线人工操作。

早期工作~\citep{chen2022persformer,lstr,can2021structured}利用线形先验从前视图图像中感知开放形状的车道线。这类方法局限于单视图感知（Perception），无法处理其他任意形状的地图元素。
随着鸟瞰视图（Bird's Eye View, BEV）表示学习的发展，近期工作~\citep{gkt,cvt,fiery,bevformer}通过BEV语义分割预测栅格化地图（Rasterized Map）。然而，栅格化地图缺乏向量化实例级信息，如车道结构等，这对下游任务（Downstream Tasks）（如运动预测和规划）至关重要。
为构建向量化高精地图，HDMapNet~\citep{hdmapnet}对逐像素分割结果进行分组，这需要复杂且耗时的后处理（Post-processing）。VectorMapNet~\citep{vectormapnet}将每个地图元素表示为点序列（Point Sequence），采用级联的从粗到细（Coarse-to-fine）框架，利用自回归解码器（Auto-regressive Decoder）逐点预测，导致推理时间较长。

现有在线向量化高精地图构建方法受限于效率，无法应用于实时场景。
最近，DETR~\citep{detr}采用简洁高效的编码器-解码器（Encoder-Decoder）Transformer架构，实现了端到端目标检测（Object Detection）。
% and meticulously designed components.
% Recently, DETR~\citep{detr} treats object detection as parallel set prediction. It employs a simple but efficient encoder-decoder Transformer architecture to  predict all objects, getting rid of post-processing.
% It is natural to ask a question: \textit{Can we efficiently construct vectorized HD map in a structured and end-to-end fashion?}
% Is it possible to design a DETR-like paradigm for efficient and end-to-end vectorized HD map construction? In this paper, we present \textbf{Map} \textbf{TR}ansformer (MapTR) to achieve it.

这自然引出一个问题：\textit{能否设计类似DETR的范式来实现高效的端到端向量化高精地图构建？}本文通过提出的\textbf{Map} \textbf{TR}ansformer (MapTR)表明答案是肯定的。

 % we present \textbf{Map} \textbf{TR}ansformer (MapTR), an efficient end-to-end online vectorized HD map construction method with unified modeling and  architecture.
% To answer the question, we need to investigate the vectorized HD map in depth. Vectorized HD map contains abundant and precise instance-level road information for various semantics (\eg, lane divider, pedestrian crossing and road boundary) and arbitrary shapes (\eg, open-shape polyline and close-shape polygon).
% And all the map elements are recorded in vector data format.

% An intuitive solution is that we define the arbitrary shape as a point set in a fixed order and leverage DETR-like architecture and loss to regress each point. All the map elements are geometrically abstracted as  directed polylines~\citep{vectormapnet}. However, such a simple definition can not accurately describe the geometrical shape, incurring ambiguity (refer to Fig.~\ref{fig:ambiguity-case}).


与目标检测中可将目标简单抽象为边界框（Bounding Box）不同，向量化地图元素具有更动态的形状。
% Compared to bounding box in the object detection, vectorized map elements have more dynamic shapes.
为精确描述地图元素，本文提出统一建模方法。将每个地图元素建模为带有等价排列集合的点集。点集确定地图元素位置，排列组包含与该几何形状对应的所有可能点集组织顺序，从而避免形状模糊性。

基于排列等价建模，本文设计结构化框架，以车载相机图像为输入，输出向量化高精地图。将在线向量化高精地图构建简化为并行回归（Parallel Regression）问题。提出层次化查询嵌入以灵活编码实例级和点级信息。所有实例及其所有点通过统一Transformer结构同时预测。训练流程被归结为层次化集合预测（Set Prediction）任务，依次执行层次化二分匹配以分配实例和点。通过提出的点对点损失（Point2point Loss）和边缘方向损失（Edge Direction Loss），在点级和边缘级监督几何形状。

综合以上全部设计，本文提出MapTR——一种采用统一建模和架构的高效端到端在线向量化高精地图构建方法。
MapTR在nuScenes~\citep{nuscenes}数据集上达到现有向量化地图构建方法中最佳性能和效率。具体而言，MapTR-nano在RTX 3090上实现实时推理速度（25.1 FPS），比现有基于相机的当前最优方法快8倍，同时mAP高5.0。

即使与现有当前最优多模态方法相比，MapTR-nano的mAP高0.7且推理速度快8倍，MapTR-tiny的mAP高13.5且推理速度快3倍。
% MapTR-tiny significantly outperforms the existing state-of-the-art multi-modality method by $13.5$ mAP while being faster.
如图~\ref{fig:visualization}所示，MapTR在复杂多样的驾驶场景中保持稳定鲁棒的地图构建质量。

本文贡献总结如下：
\begin{itemize}
    \item 提出统一的排列等价建模方法用于地图元素，即将地图元素建模为带有等价排列集合的点集，该方法准确描述地图元素形状并稳定学习过程。
    % simplify the learning process?
    \item 基于该建模方式，提出MapTR——一种面向高效在线向量化高精地图构建的结构化端到端框架。
    设计层次化查询嵌入方案以灵活编码实例级和点级信息，执行层次化二分匹配进行地图元素学习，通过提出的点对点损失和边缘方向损失在点级和边缘级监督几何形状。
    \item MapTR是首个实时且当前最优（SOTA）的向量化高精地图构建方法，在复杂多样的驾驶场景中具有稳定鲁棒的性能。
\end{itemize}


\section{相关工作}
\paragraph{高精地图构建（HD Map Construction）.}
近年来，随着2D到BEV方法~\citep{Ma2022VisionCentricBP}的发展，高精地图构建被归结为基于车载相机环视图像数据的分割问题。\cite{gkt,cvt,fiery,bevformer,lss,polarbev}通过BEV语义分割生成栅格化地图。
为构建向量化高精地图，HDMapNet~\citep{hdmapnet}通过启发式且耗时的后处理对逐像素语义分割结果进行分组以生成实例。
% VectorMapNet~\citep{vectormapnet} adopts a two-stage pipeline. The first stage utilizes set prediction method~\citep{detr,yolos} to detect coarse keypoints and the second stage utilizes sequence generation method  to sequentially predict the next point of the map element.
% VectorMapNet~\citep{vectormapnet} represents each map element as a point sequence, and utilizes auto-regressive decoder to predict  points sequentially.
% it impose incurring  ambiguity.
% (2) VectorMapNet  predicts points in a recurrent manner and adopts a cascaded coarse-to-fine framework, leading to longer inference time
% (3) The recurrent nature of auto-regressive decoder incurs the problem of accumulated error
VectorMapNet~\citep{vectormapnet}作为首个端到端框架，采用两阶段从粗到细框架并利用自回归解码器逐点预测，导致推理时间长且存在排列模糊性。
与VectorMapNet不同，MapTR引入统一的地图元素建模方式，解决了模糊性并稳定了学习过程。MapTR构建了结构化的并行单阶段框架，效率大幅提升。




\paragraph{车道线检测（Lane Detection）.}
车道线检测（Lane Detection）可视为高精地图构建的子任务，专注于检测道路场景中的车道元素。由于大多数车道线检测数据集仅提供单视图标注且聚焦于开放形状元素，相关方法局限于单视图。
LaneATT~\citep{tabelini2021keep}利用基于锚点的深度车道线检测模型，在准确率和效率之间取得良好平衡。LSTR~\citep{lstr}采用Transformer架构直接输出车道形状模型参数。GANet~\citep{wang2022keypoint}将车道线检测归结为关键点估计和关联问题，采用自底向上的设计方案。\cite{feng2022rethinking}提出基于参数化贝塞尔曲线（Bezier Curve）的车道线检测方法。\cite{garnett20193d}不直接在2D图像坐标中检测车道，而是提出3D-LaneNet在BEV中进行3D车道线检测。STSU~\citep{can2021structured}将车道线表示为BEV坐标中的有向图，采用基于曲线的贝塞尔方法从单目相机图像预测车道线。Persformer~\citep{chen2022persformer}提供更好的BEV特征表示并优化锚点设计，同时统一2D和3D车道线检测。
MapTR不局限于在有限单视图中检测车道线，而是通过统一建模和学习框架感知$360^\circ$水平视野内的各类地图元素。

\paragraph{基于轮廓的实例分割（Contour-based Instance Segmentation）.}
与MapTR相关的另一条研究路线是基于轮廓（Contour）的2D实例分割~\citep{Zhu_2022_CVPR, polarmask, xu2019explicit,liu2021dance}。这些方法将2D实例分割重新定义为目标轮廓预测任务，估计轮廓顶点的图像坐标。CurveGCN~\citep{ling2019fast}利用图卷积网络（Graph Convolution Network）预测多边形边界。
% Deepsnake proposes a two-stage contour evolution process and designs circular convolution to exploit the features on the contour.
\cite{Lazarow_2022_CVPR,PolyTransform,building_seg,peng2020deep}依赖中间表示并采用两阶段范式，即第一阶段执行分割/检测生成顶点，第二阶段将顶点转换为多边形。
这些工作将2D实例掩码的轮廓建模为多边形，其建模方法无法处理线形地图元素，不适用于地图构建。相比之下，MapTR专为高精地图构建设计，以统一方式建模各类地图元素。此外，MapTR不依赖中间表示，流程高效紧凑。


\section{MapTR}
\subsection{排列等价建模（Permutation-equivalent Modeling）\label{sec:modeling}}


\begin{figure}[]
    \begin{center}
    \includegraphics[width=\linewidth]{fig/example.pdf}
    \end{center}
    \vspace*{-0.7cm}
    \hspace*{1.5cm} { (a) 折线（Polyline）} \hspace*{5.0cm} { (b) 多边形（Polygon）}
    \vspace*{-0.2cm}
    \caption{说明地图元素关于起点和方向模糊性的典型案例。
    (a) 折线：对于两条对向车道之间的车道线，定义其方向较为困难。车道线的两个端点均可视为起点，点集可按两个方向组织。
    (b) 多边形：对于人行横道，
    多边形的每个点均可视为起点，多边形可按两个相反方向（逆时针和顺时针）连接。}
    \label{fig:ambiguity-case}
    \vspace*{-0.5cm}
\end{figure}




MapTR旨在以统一方式建模和学习高精地图。高精地图是向量化静态地图元素的集合，包括人行横道、车道线、道路边界等。在结构化建模中，MapTR将地图元素几何抽象为闭合形状（如人行横道）和开放形状（如车道线）。通过沿形状边界顺序采样点，闭合形状元素离散为多边形（Polygon），开放形状元素离散为折线（Polyline）。

初步地，多边形和折线均可表示为有序点集 ${V}^{F}= [v_0, v_1, \dots, v_{N_v-1}]$（见图~\ref{fig:modeling}（Vanilla））。$N_v$ 表示点的数量。然而，点集的排列并未明确定义且不唯一。多边形和折线存在许多等价排列。
例如，如图~\ref{fig:ambiguity-case}（a）所示，对于两条对向车道之间的车道线（折线），定义其方向较为困难。车道线的两个端点均可视为起点，点集可按两个方向组织。
在图~\ref{fig:ambiguity-case}（b）中，对于人行横道（多边形），点集可按两个相反方向（逆时针和顺时针）组织，且循环改变点集的排列对多边形的几何形状无影响。
将固定排列强加于点集作为监督是不合理的。强加的固定排列与其他等价排列相矛盾，阻碍了学习过程。

 % not considering all the equivalent permutations.


为弥补这一差距，MapTR使用 $\mathcal{V}=(V,\Gamma)$ 建模每个地图元素。
$V = \{v_{j}\}_{j=0}^{N_v-1}$ 表示地图元素的点集（$N_v$ 为点数）。
$\Gamma = \{\gamma^{k}\}$ 表示点集 $V$ 的等价排列组，涵盖所有可能的组织顺序。


\begin{figure}[]
    \begin{center}
    \includegraphics[width=\linewidth]{fig/modeling.pdf}
    \end{center}
    \vspace*{-0.3cm}
    \caption{MapTR排列等价建模示意图。地图元素被几何抽象并离散为折线和多边形。
    MapTR使用 $(V, \Gamma)$（点集 $V$ 和等价排列组 $\Gamma$）建模每个地图元素，避免了模糊性并稳定了学习过程。}
    \label{fig:modeling}
    \vspace*{-0.5cm}
\end{figure}

Specifically, for polyline element (see Fig.~\ref{fig:modeling} (left)),  $\Gamma$ includes $2$ kinds of equivalent permutations:
\begin{equation}
\begin{aligned}
&\Gamma_{\rm{polyline}} = \{\gamma^{0}, \gamma^{1} \}
\begin{cases}
&\gamma^{0}(j) = j \mod N_v,\\
&\gamma^{1}(j) = (N_v - 1) - j \mod N_v.\\
\end{cases}
\end{aligned}
\end{equation}

For polygon element (see Fig.~\ref{fig:modeling} (right)),  $\Gamma$ includes $2\times N_v$ kinds of equivalent permutations:
\begin{equation}
\begin{aligned}
&\Gamma_{\rm{polygon}} = \{\gamma^{0}, \dots, \gamma^{2 \times N_v-1}\}
\begin{cases}
&\gamma^{0}(j) = j \mod N_v,\\
&\gamma^{1}(j) = (N_v - 1) - j \mod N_v,\\
&\gamma^{2}(j) = (j + 1) \mod N_v,\\
&\gamma^{3}(j) = (N_v - 1) - (j + 1) \mod N_v,\\
&...\\
&\gamma^{2 \times N_v - 2}(j) = (j + N_v - 1) \mod N_v,\\
&\gamma^{2 \times N_v - 1}(j) = (N_v - 1) - (j + N_v - 1) \mod N_v.
\end{cases}
\end{aligned}
\end{equation}




通过引入等价排列概念，MapTR以统一方式建模地图元素，解决了模糊性问题。
% Based on such modeling,
MapTR进一步引入层次化二分匹配（见第~\ref{matching}节和第~\ref{sec:e2e-training}节）用于地图元素学习，并设计结构化编码器-解码器Transformer架构以高效预测地图元素（见第~\ref{sec:architecture}节）。

\subsection{层次化匹配（Hierarchical Matching）\label{matching}}
MapTR遵循DETR~\citep{detr,yolos}的端到端范式，单次并行推断固定大小的 $N$ 个地图元素集合。$N$ 设置为大于场景中典型地图元素数量。将 $N$ 个预测地图元素的集合记为 $\hat{Y} = \{\hat{y}_i \}_{i=0}^{N-1}$。真实（GT）地图元素集合用 $\varnothing$（无目标）填充至大小 $N$，记为 $Y=\{y_i\}_{i=0}^{N-1}$。$y_i=(c_i, V_i, \Gamma_i)$，其中 $c_i$、$V_i$ 和 $\Gamma_i$ 分别为GT地图元素 $y_i$ 的目标类别标签、点集和排列组。$\hat{y}_i=(\hat{p}_i, \hat{V}_i)$，其中 $\hat{p}_i$ 和 $\hat{V}_i$ 分别为预测分类得分和预测点集。
为实现结构化地图元素建模和学习，MapTR引入层次化二分匹配，即依次执行实例级匹配和点级匹配。


\paragraph{实例级匹配（Instance-level Matching）.\label{sec:ins-lvl-matching}}

首先，需要在预测地图元素 $\{\hat{y}_i \}$ 和GT地图元素 $\{y_i \}$ 之间找到最优的实例级标签分配 $\hat{\pi}$。$\hat{\pi}$ 是 $N$ 个元素的排列（$\hat{\pi} \in \Pi_N$），具有最低的实例级匹配代价：
\begin{equation}
% \small
\begin{gathered}
\hat{\pi} = \argmin_{\pi \in \Pi_N} \sum_{i=0}^{N-1} \mathcal{L}_{\rm ins\_match} (\hat{y}_{\pi(i)}, y_i). \label{eq:argmin_inst_loss}
\end{gathered}
\end{equation}

$\mathcal{L}_{\rm ins\_match}(\hat{y}_{\pi(i)}, y_i)$ 是预测 $\hat{y}_{\pi(i)}$ 与GT $y_i$ 之间的成对匹配代价，同时考虑地图元素的类别标签和点集位置：
\begin{equation}
\begin{gathered}
\mathcal{L}_{\rm ins\_match}(\hat{y}_{{\pi}(i)},  y_i ) =
\mathcal{L}_{\rm{Focal}}(\hat{p}_{{\pi}(i)}, c_i) + \mathcal{L}_{\rm position}(\hat{V}_{\pi(i)}, V_i).
\end{gathered}
\end{equation}
 % -\log\hat{p}_{\pi(i)} (c_i) 
$\mathcal{L}_{\rm{Focal}}(\hat{p}_{{\pi}(i)}, c_i)$ 是类别匹配代价项，定义为预测分类得分 $\hat{p}_{{\pi}(i)}$ 与目标类别标签 $c_i$ 之间的Focal Loss~\citep{focal}。
$\mathcal{L}_{\rm position}(\hat{V}_{\pi(i)}, V_i)$ 是位置匹配代价项，反映预测点集 $\hat{V}_{\pi(i)}$ 与GT点集 $V_i$ 之间的位置相关性（详见第~\ref{sec:more_ablation}节）。
采用匈牙利算法（Hungarian Algorithm）寻找最优的实例级分配 $\hat{\pi}$，遵循DETR。


\paragraph{点级匹配（Point-level Matching）.}
完成实例级匹配后，每个预测地图元素 $\hat{y}_{\hat{\pi}(i)}$ 被分配一个GT地图元素 $y_i$。然后，对每个分配正标签的预测实例（$c_i\neq\varnothing$），执行点级匹配以在预测点集 $\hat{V}_{\hat{\pi}(i)}$ 和GT点集 $V_{i}$ 之间找到最优的点对点分配 $\hat{\gamma} \in \Gamma$。$\hat{\gamma}$ 从预定义排列组 ${\Gamma}$ 中选出，具有最低的点级匹配代价：
\begin{equation}
% \small  Distance
\begin{gathered}
\hat{\gamma} = \argmin_{\gamma \in {\Gamma}} \sum_{j=0}^{N_v-1} 
D_{\rm{Manhattan}}(\hat{v}_{j}, v_{ \gamma(j)}). \label{eq:argmin_pts_loss}
\end{gathered}
\end{equation}
$D_{\rm{Manhattan}}(\hat{v}_{j}, v_{ \gamma(j)})$ 是预测点集 $\hat{V}$ 的第 $j$ 个点与GT点集 $V$ 的第 $\gamma(j)$ 个点之间的曼哈顿距离（Manhattan Distance）。


% \subsection{End-to-end Training
\subsection{训练损失（Training Loss）
\label{sec:e2e-training}}
MapTR基于最优的实例级和点级分配（$\hat{\pi}$ 和 $\{\hat{\gamma_i}\}$）进行训练。损失函数由三部分组成：分类损失、点对点损失和边缘方向损失：
\begin{equation}
\begin{gathered}
   \mathcal{L} = \lambda \mathcal{L}_{\rm{cls}} + \alpha \mathcal{L}_{\rm{p2p}} + \beta \mathcal{L}_{\rm{dir}},
\end{gathered}    
\end{equation}
其中 $\lambda$、$\alpha$ 和 $\beta$ 为平衡不同损失项的权重。


\paragraph{分类损失（Classification Loss）.}
基于实例级最优匹配结果 $\hat{\pi}$，
每个预测地图元素被分配一个类别标签\oldnew{(or 'no object' $\varnothing$)}{}。分类损失是Focal Loss项，公式化为：
\begin{equation}
\begin{gathered}
\mathcal{L}_{\rm{cls}} = \sum_{i=0}^{N-1} \mathcal{L}_{\rm{Focal}}(\hat{p}_{\hat{\pi}(i)}, c_i).
\end{gathered}
\end{equation}



\paragraph{点对点损失（Point2point Loss）.}
点对点损失监督每个预测点的位置。
对于索引为 $i$ 的每个GT实例，
根据点级最优匹配结果 $\hat{\gamma}_i$，
每个预测点 $\hat{v}_{\hat{\pi}(i),j}$ 被分配一个GT点 $v_{i, \hat{\gamma}_i(j)}$。
点对点损失定义为每个分配点对之间的曼哈顿距离：

\begin{equation}
\begin{gathered}
    \mathcal{L}_{\rm{p2p}} = \sum_{i=0}^{N-1}   \mathbbm{1}_{\{c_i\neq \varnothing\}}    \sum_{j=0}^{N_v-1} D_{\rm {Manhattan}}(\hat{v}_{\hat{\pi}(i),j},  v_{i, \hat{\gamma}_i(j)}).
\end{gathered}    
\end{equation}

\paragraph{边缘方向损失（Edge Direction Loss）.}
点对点损失仅监督折线和多边形的节点点，未考虑边（相邻点之间的连接线）。为精确表示地图元素，边方向很重要。因此，进一步设计边缘方向损失以在更高边缘级监督几何形状。具体而言，考虑成对的预测边 $\boldsymbol{\hat{e}_{\hat{\pi}(i),j}}$ 和GT边 $\boldsymbol{e_{i, \hat{\gamma}_i(j)}}$ 的余弦相似度（Cosine Similarity）：
  
\begin{equation}
\begin{gathered}
    \mathcal{L}_{\rm{dir}} = - \sum_{i=0}^{N-1}   \mathbbm{1}_{\{c_i\neq \varnothing\}}  
    \sum_{j=0}^{N_v-1}  {\rm cosine\_similarity}(\boldsymbol{\hat{e}_{\hat{\pi}(i),j}}, \boldsymbol{e_{i, \hat{\gamma}_i(j)}}),\\
    \boldsymbol{\hat{e}_{\hat{\pi}(i),j}}=\hat{v}_{\hat{\pi}(i),j}  - \hat{v}_{\hat{\pi}(i),(j+1) \rm{mod} N_v},\\
    \boldsymbol{e_{i, \hat{\gamma}_i(j)}}=v_{i, \hat{\gamma}_i(j)} - v_{i, \hat{\gamma}_i(j+1) \rm{mod} N_v}.
\end{gathered}    
\end{equation}

\subsection{网络架构（Architecture）\label{sec:architecture}}
MapTR采用编码器-解码器范式，整体架构如图~\ref{fig:framework}所示。

\paragraph{输入模态（Input Modality）.}
MapTR以车载相机环视图像为输入。MapTR也兼容其他车载传感器（如激光雷达（LiDAR）和雷达（RADAR））。将MapTR扩展到多模态数据直接且简单。得益于合理的排列等价建模，即使仅使用相机输入，MapTR也显著优于使用多模态输入的其他方法。

\paragraph{地图编码器（Map Encoder）.}
MapTR的地图编码器从多台车载相机图像中提取特征，并将这些特征转换为统一的特征表示，即BEV表示。给定多视图图像 $\mathcal{I}=\{I_1, \ldots, I_K\}$，使用常规骨干网络（Backbone）生成多视图特征图 $\mathcal{F}=\{F_1, \ldots, F_K\}$。然后将2D图像特征 $\mathcal{F}$ 转换为BEV特征 $\mathcal{B} \in \mathbb{R}^{H\times W \times C}$。默认采用GKT~\citep{gkt}作为基本2D到BEV转换模块，因其易于部署且高效。MapTR兼容其他转换方法并保持稳定性能，例如CVT~\citep{cvt}、LSS~\citep{lss,liu2022bevfusion,bevdepth,bevdet}、Deformable Attention~\citep{bevformer,deformdetr}和IPM~\citep{ipm}。消融实验见表~\ref{tab:2dtobev}。

\paragraph{地图解码器（Map Decoder）.}
本文提出层次化查询嵌入方案以显式编码每个地图元素。具体而言，定义一组实例级查询 $\{ q^{\rm{ins}}_i\}_{i=0}^{N-1}$ 和一组所有实例共享的点级查询 $\{q^{\rm{pt}}_j\}_{j=0}^{N_v-1}$。 
每个地图元素（索引$i$）对应一组层次化查询 $\{q^{\rm{hie}}_{ij}\}_{j=0}^{N_v-1}$。第$i$个地图元素第$j$个点的层次化查询公式化为：
\begin{equation}
\begin{gathered}
    q^{\rm{hie}}_{ij} =  q^{\rm{ins}}_i + q^{\rm{pt}}_j.
\end{gathered}
\end{equation}


地图解码器包含多个级联的解码器层，迭代更新层次化查询。在每个解码器层中，采用MHSA使层次化查询相互交换信息（包括实例间和实例内）。然后采用Deformable Attention~\citep{deformdetr}使层次化查询与BEV特征交互，受BEVFormer~\citep{bevformer}启发。每个查询 $q^{\rm{hie}}_{ij}$ 预测参考点 $p_{ij}$ 的二维归一化BEV坐标 $(x_{ij},y_{ij})$。然后在参考点周围采样BEV特征并更新查询。

地图元素通常具有不规则形状且需要长距离上下文。每个地图元素对应一组分布灵活动态的参考点 $\{p_{ij}\}_{j=0}^{N_v-1}$。参考点 $\{p_{ij}\}_{j=0}^{N_v-1}$ 可适应地图元素的任意形状，并为地图元素学习捕获信息丰富的上下文。

MapTR的预测头简单，由分类分支和点回归分支组成。分类分支预测实例类别得分。点回归分支预测点集 $\hat{V}$ 的位置。对于每个地图元素，输出 $2N_v$ 维向量，表示 $N_v$ 个点的归一化BEV坐标。




\section{实验}


\paragraph{数据集与指标（Dataset and Metric）.}
在nuScenes~\citep{nuscenes}数据集上评估MapTR，该数据集包含1000个场景，每个场景约20秒。关键样本以2Hz频率标注。每个样本包含来自6个相机的RGB图像，覆盖自车$360^\circ$水平视野。遵循先前方法~\citep{hdmapnet,vectormapnet}，选择三种地图元素进行公平评估：人行横道、车道线和道路边界。感知范围为X轴$[-15.0m, 15.0m]$和Y轴$[-30.0m, 30.0m]$。采用平均精度（Average Precision, AP）评估地图构建质量。使用Chamfer距离 $D_{Chamfer}$ 判断预测与GT是否匹配。在多个 $D_{Chamfer}$ 阈值（$\tau \in T, T=\{0.5, 1.0, 1.5\}$）下计算 $\rm{AP}_{\tau}$，然后对所有阈值取平均作为最终AP指标：

\begin{equation}
\rm{AP} = \frac{1}{|T|} \sum_{\tau \in T} \rm{AP}_{\tau}.
\end{equation}



\paragraph{实现细节（Implementation Details）.}
MapTR使用8张NVIDIA GeForce RTX 3090 GPU进行训练。采用AdamW~\citep{adamw}优化器和余弦退火（Cosine Annealing）调度。MapTR-tiny采用ResNet50~\citep{resnet}作为骨干网络，总批量大小为32（包含6视图图像）。所有消融实验基于MapTR-tiny训练24个epoch。MapTR-nano专为实时应用设计，采用ResNet18作为骨干网络。更多细节见附录~\ref{sec:more_details}。

We train MapTR-tiny with a total batch size of $32$ (containig 6 view images). All ablation studies are based on MapTR-tiny trained with $24$ epochs.
% MapTR-nano is designed for real-time application.  We adopts ResNet18 as the backbone. We set the size of each BEV grid to $0.75m$ and stack $2$ transformer decoder layers. And we train MapTR-nano with a total batch size of $192$. As for hyper-parameters of loss weight, $\lambda$ is set to $2$, $\alpha$ is set to $5$, and $\beta$ is set to $5e^{-3}$. More details are provided in Appendix~\ref{sec:more_details}.

\section{结论}
MapTR是一种面向高效在线向量化高精地图构建的结构化端到端框架，采用简洁的编码器-解码器Transformer架构和层次化二分匹配，基于提出的排列等价建模进行地图元素学习。大量实验表明，所提方法能够在具有挑战性的nuScenes数据集上精确感知任意形状的地图元素。期望MapTR能够作为自动驾驶系统的基本模块，推动下游任务（如运动预测和规划）的发展。

\paragraph{数据增强（Data Augmentation）.}
源图像分辨率为$1600\times900$。对于MapTR-nano，将源图像按0.2比例缩放。对于MapTR-tiny，将源图像按0.5比例缩放。默认使用颜色抖动（Color Jitter）。

\paragraph{模型设置（Model Setting）.}
所有实验中，训练时$\lambda$设为2，$\alpha$设为5，$\beta$设为$5e^{-3}$。对于MapTR-tiny，实例级查询数和点级查询数分别设为50和20。将每个BEV网格大小设为$0.3m$，堆叠6个Transformer解码器层。MapTR-tiny的总批量大小为32（包含6视图图像），学习率为$6e^{-4}$，骨干网络的学习率乘子为0.1。所有消融实验基于MapTR-tiny训练24个epoch。对于MapTR-nano，实例级查询数和点级查询数分别设为100和20。将每个BEV网格大小设为$0.75m$，堆叠2个Transformer解码器层。MapTR-nano训练110个epoch，总批量大小为192，学习率为$4e^{-3}$，骨干网络的学习率乘子为0.1。采用GKT~\citep{gkt}作为MapTR的默认2D到BEV模块。

\paragraph{数据集预处理（Dataset Preprocessing）.}
按照\cite{vectormapnet, hdmapnet}处理地图标注。提取自车感知范围内的地图元素作为GT地图元素。默认感知范围为X轴$[-15.0m, 15.0m]$和Y轴$[-30.0m, 30.0m]$。
